# tools — USB / Wi-Fi 网页调试台

`web/` 是无需 npm 安装、无需外网的静态网页，通过 Web Serial 或 Wi-Fi WebSocket 与板子通信，适配本仓库的 [USB JSON 协议](../protocol/usb_protocol.md)和 [Wi-Fi 协议](../docs/wifi.md)。

## 启动

在仓库根目录执行：

```powershell
python tools/serve.py --open
```

Windows 也可双击 [`start_web.cmd`](start_web.cmd)，从任意当前目录启动服务并打开浏览器。启动窗口需要保持打开；按 Ctrl+C 停止服务。若默认浏览器不是 Chrome / Edge，请在桌面 **Chrome / Edge** 手动打开 <http://127.0.0.1:8776/>。

在「USB 串口」区域点击「选择串口并连接」，然后在浏览器自带的选择弹窗中选中板子的 COM 端口并确认。顶部也有相同入口。首次访问需要通过弹窗授权，页面不会直接列出未经授权的所有 COM 口；连接后显示设备的 USB VID/PID。若在演示模式，请先点击「退出演示」。Web Serial 需要支持该 API 的浏览器及安全上下文；本地回环地址可用，普通远程 HTTP 地址不可用。实现依据 [Chrome Web Serial 文档](https://developer.chrome.com/docs/capabilities/serial)。

先关闭 ESP-IDF monitor 或其他串口终端，避免端口占用。波特率默认 115200，可在连接前调整。连接成功后只发送 `get` 和 `sub`，不改动板端现有电机状态。用完按 Ctrl+C 停止 HTTP 服务。启动脚本只监听本机，并固定 JavaScript 模块的 MIME 类型，避免 Windows 默认文件关联导致页面不执行 JS；端口占用时可用 `python tools/serve.py --port 8777`。

没有板子时可点击「演示模式」，体验曲线和控制界面；模拟记录和 CSV 都带 demo 标记，退出演示后清空。

若网页无法访问，先检查启动窗口是否仍在运行、有没有端口占用错误。关闭旧的 `serve.py` 启动窗口后重新启动，或执行 `python tools/serve.py --port 8777 --open` 并访问对应的 8777 地址。端口被占用并不保证旧服务仍能响应；浏览器一直等待时需重启旧服务。HTTP 服务与板子 USB 独立，没有接板子也应能打开网页。

## 功能

- 连接：USB / Wi-Fi 两种方式；USB 配置 SSID/password、开关板端 Wi-Fi 并读取 IP 与接入密钥。关闭保留配置并释放无线资源，保存配置不自动开启；Wi-Fi 使用同一套遥测和电机控制界面。

- IMU：三轴加速度 g、三轴角速度 °/s、读取状态、板端卡尔曼开关、滤波前后对比及独立滤波波形。
- 姿态：板端四元数驱动的三维方块、横滚／俯仰／相对航向显示，以及仅改变网页参考的姿态归零。
- 电机/编码器：模式、角度 rad/°、角速度 rad/s、累计计数、实际 PWM、限幅标志、位置误差。
- 电流/力矩：实测/目标电流、电流曲线、目标/实测力矩、DOB 电机/外力矩，力矩单位 N·m。
- 调试：订阅/暂停、读取参数、设置遥测频率、开环 PWM、停止电机、编码器清零、加热占空比、NVS 保存、控制参数修改和自定义 JSON 命令。
- CSV：导出最近 30,000 帧（50 Hz 时约 10 分钟，100 Hz 时约 5 分钟）；带浏览器接收时间、usb/wifi/demo 来源与所有固件遥测字段。关闭/刷新页面清空记录。
- 串口：处理分包、粘包、CRLF、UTF-8、ANSI 日志和 `>>` JSON 回复；显示板端错误及命令超时，断开后数据明确标记为历史数据。

## 操作语义与限制

- 只有点击发送才改变控制参数。读取参数后回填输入框，只发送手动修改项；未收到回复不宣称已执行。
- 网页频率选项最高提供 100 Hz；板端通过独立 `esp_timer` 按配置周期唤醒遥测任务，100 Hz 为 10 ms，不再在组包/发送后额外等待一个周期。超过处理能力时跳过积压通知，不连续补发。接收速率按收到的完整遥测帧计数，实际频率受板端负载、USB / 网络带宽及浏览器调度影响。
- 「读取诊断」可查看最近/最高总耗时、快照/组包/USB 写入/Wi-Fi 入队分段耗时、组包失败次数及累计跳过的发送通知；100 Hz 周期为 10 ms，可据此排查发送任务是否赶不上周期。通知丢弃计数不等于 USB 丢包数，耗时包含任务抢占和通信等待。
- 固件接收缓冲为 256 字节，网页限制每条 JSON 正文不超过 255 字节；修改太多参数时会提示分批发送。
- 「暂停订阅」只暂停遥测；「停止电机」发送 `{"cmd":"duty","v":0}`，退出闭环并清除开环输出。
- 「停机并断开」依次发送 `duty=0`、`heater=0`、`unsub`，显示确认结果后释放串口。拔线或关闭网页无法保证板端停机，操作前应先点击停止电机。
- 固件开环 duty 不使用闭环 `duty_max`；网页允许 −1 到 1，初调请手动使用小占空比。
- 当前协议按 cmd 匹配回复，没有请求 ID；同名命令等待回复期间通常不重复发送。停止命令仍会优先进入发送队列，但前一个 duty 未回复时只能报告已发送、无法单独确认。超时后迟到的同名回复存在协议歧义，需结合遥测核对。
- IMU 遥测提供原始／滤波六轴和板端姿态四元数 `quat=[w,x,y,z]`，没有温度和 nFAULT 字段；固件标识可通过 `diag` 查看。电流符号按 duty 合成，力矩值依赖 Kt/机械参数标定；ADC 失败不会自动切换 DOB 电枢回退。
- 当前固件用 `BSP_USB_JSON_CAPACITY=1024` 统一上层 JSON 容量，底层另外留出 `>>`、换行及 NUL 空间。使用旧固件时可能丢弃较长的参数回复，需要重新烧录当前固件。

## get/sub 超时诊断

先在网页「停机并断开」并关闭 IDF monitor，再在 ESP-IDF Python 环境执行：

```powershell
python tools/usb_probe.py --list
python tools/usb_probe.py --port COM3
python tools/usb_probe.py --port COM3 --diag
```

该工具不切换 DTR/RTS、不发送电机或加热命令，发送 `get`、`sub`、`unsub` 并打印回复；加 `--diag` 时还发送 `diag`。正常结果为 `get_ack=True sub_ack=True`，且 `telemetry_frames` 大于 0。端口被占用会明确提示；原生 ESP32-C3 USB 设备通常为 VID/PID `303A:1001`，不要选蓝牙串口。

若诊断没有任何 RX，检查板子是否正在正常运行而非下载模式，以及烧录的固件是否与当前源码一致。若持续出现启动日志/abort/backtrace，说明板端没有运行到 USB 命令服务。修正后的固件启动应包含 `USB JSON ready (get/sub), payload_capacity=1024`。

IMU 初始化失败时当前固件继续提供 USB/编码器诊断，本次启动关闭电机闭环和加热，上报 `imu_ok=0` 及芯片 ID；网页显示「IMU 读取失败」，无效六轴读数显示为 `—`。本次板子的 IMU 故障已由修复虚焊解决；类似问题需检查供电、SPI、片选和焊接，再复位重新初始化。日志中的 SPI ESP_OK 仅表示主控完成传输。

连接后可在 IMU 面板点击「读取诊断」（`diag` 命令），查看缓存的初始化错误、两颗芯片 ID、SPI 错误、运行时间、复位原因和固件标识，无需抓取开机日志。这个命令不重新初始化 IMU，也不改电机状态；旧固件返回 unknown 时需要更新固件。网页默认不将遥测原文刷入通信日志，需要时勾选「显示遥测原文」。主动拔线、复位或烧录造成的 `The device has been lost` 是连接失效提示，不能据此判断固件崩溃。

只有万用表时，可在 IMU 初始化失败的状态点击「探测 SPI」（`imu_probe`）。它测试 Mode0/Mode3 × 8 MHz/1 MHz/250 kHz 的原始 CHIP_ID 字节，以及空闲 MISO 对弱上/下拉的响应。探测不写传感器寄存器、不复位、不改电机参数；正常初始化的 IMU 会拒绝此命令。SPI 事务现在先配置总线时钟极性再拉低 CS，并保证片选建立/保持时间，避免 BMI088 自动选择模式时看到错误的 SCK 空闲电平。探测不能替代波形或 PCB/焊接检查，也不会把 `imu_ok` 改为正常。

空闲电平测试错误 259 时，−1 并非实际电平；旧版曾将 SPI 外设控制的 OE 配置误判为普通输出，新版已修正并显示 GPIO6 配置。

## 电机控制

板端控制区提供开环 PWM、阻抗力反馈、位置 PID、力矩／电流 PI 四种模式。选择模式只切换表单，点击发送才执行；闭环启动用一条 `set` 同时发送模式及该模式的完整参数，收到回复后才确认。各模式停止均发送 `duty=0` 切回开环，命令等待回复时停止按钮仍可操作。

- 开环：数字框或百分比滑块编辑占空比，反向按钮修改目标，点击「发送 PWM」执行。固件开环不使用 `duty_max`。
- 阻抗：设置中心角、K/B、PWM 上限和软限位；当前固件 K/B 的计算结果直接用于占空比，不能视为已标定的物理力矩。
- 位置：设置目标角及 PID 增益，支持度/弧度切换，发送时统一转为弧度；「以当前位置为目标」只填入新鲜编码器遥测的角度，不立即运行。
- 力矩／电流：设置力矩、Kt、PI、电流和 PWM 限幅，也可将目标电流换算为力矩；显示请求电流与限幅后电流。该固件模式不执行角度软限位。

板端运行模式、PWM、电流及位置误差来自遥测，暂停订阅或断开后标记为历史状态。位置曲线显示编码器角度，位置 PID 模式下通过角度加位置误差显示板端有效目标。编码器与 DOB 参数分组显示，参数回复保留等待期间的新编辑。保存 NVS 会记录当前模式和目标，上电恢复由固件执行。演示模式使用简化电机模型，不代表实板控制器性能。

IMU 初始化成功时会恢复保存的控制模式、目标和加热占空比；初始化失败时本次启动关闭闭环和加热。要让下次上电停机，先停止电机、关闭加热，再保存 NVS；开环 duty 不存档。

## 遥测频率与 NVS 保存

遥测频率的「设置（临时）」只发送 `set.telem_hz`，修改当前运行频率；要在重启后保留，需点击「保存参数至 NVS」并收到 `save` 确认。保存包含所有当前板端参数，并非仅保存遥测频率。重连会自动 `get` 读取恢复值；「接收速率」是实测到达速率，可能低于配置频率。

NVS 按钮下方说明保存范围及未发送表单的处理，并保留本次保存状态：等待板端确认、带时间的上次保存成功、板端拒绝时保存失败、超时或断线时结果未确认。等待时禁用重复保存，停止电机按钮仍可使用；演示模式明确标记模拟保存。重新连接重置提示，不把上一次设备的保存状态带到当前板子。

当前版本使用轻量 JSON 组包，减少持续遥测中的浮点格式化开销。本板 USB 设置 100 Hz 却只有约 50 帧/s 的问题已在更新后由用户确认解决；具体新帧率与耗时未记录，详见 [验证记录](../docs/firmware.md#遥测验证记录)。如再次出现偏低速率，用「读取诊断」比较当前总耗时和四段耗时：100 Hz 周期为 10 ms，持续超时会跳过积压通知；Wi-Fi 入队耗时不包含网络送达时间。最高耗时及累计计数是本次启动的历史，应结合多次诊断的增量判断。

## 输出轴编码器标定

「读取参数」后展开「编码器、DOB 与其他参数」，查看「输出轴每转计数」。当前更换的 500 r/min 电机在参数表中对应 `JGA12-N20-30`，减速比 30:1；暂按电机轴 7 PPR × 四倍频 4 × 减速比 30，设置 `enc_cpr=840`。

固件内置默认仍是原 298:1 电机的 8344，更换后需停止电机、将每转计数改为 840、发送修改并保存 NVS；重启后读取参数核对保存值。参数表未提供 PPR，7 PPR 只是沿用原电机手动粗测的推断，新电机需用规格或多圈实测确认。500 r/min 是 6 V 空载标称值，实际转速取决于电压和负载。

角度换算为 `counts × 360 / enc_cpr`，计数已包含四倍频和减速比，不再乘四或除以 30（原电机为 298）。停机并清零后，用输出轴多圈累计计数除以圈数校验标定；编辑计数、发送修改并保存 NVS，后续重启保留。修改该值同时影响速度、位置／阻抗反馈和 DOB，建议停机时进行。

固件将未带版本的旧 600、版本低于 2 的旧默认 3576，以及版本 2 的粗测默认 8292 迁移为 8344；其他自定义值保留。网页角度使用固件 `theta`，刷新网页不能替代更新固件及参数。完整迁移规则见 [固件说明](../docs/firmware.md#编码器输出轴换算)。

## IMU 滤波与对比

烧录当前固件并刷新网页后，IMU 面板提供「板端卡尔曼滤波」和「显示滤波前后对比」两个开关。前者发送独立 `imu_filter` 命令，收到板端确认后显示开启状态；超时或拒绝会显示未确认，可用「读取参数」确认实际状态。后者只控制网页显示，不发送命令。滤波默认开启，点击「保存参数至 NVS」可保留开关状态。

对比开启时数值显示原始值和卡尔曼值，曲线同色表示同一轴，原始值为虚线、滤波值为实线。旧固件仍显示原始数据，滤波开关禁用并提示更新；无效 IMU 或无效滤波结果不显示滤波读数。CSV 增加 `imu_kf_en`、`imu_kf` 和六个滤波值，关闭或无效时滤波列留空。演示模式使用模拟卡尔曼滤波，仅用于查看操作和布局；真实 USB 数据由固件滤波。板端滤波仅进行六轴降噪，网页姿态预览另见下节。

「板端卡尔曼滤波波形」独立面板分别显示滤波后三轴加速度和三轴角速度，使用同样的 X/Y/Z 颜色和最近 10 秒窗口。该面板始终显示，不受「显示滤波前后对比」开关影响；滤波关闭或数据无效时不绘制新点，已收到的有效波形保留在历史窗口内，状态标记提示当前是否正在接收。

## IMU 三维方块预览

「IMU 三轴姿态预览」直接读取板端 `quat=[w,x,y,z]`，方块面标记传感器的 ±X、±Y、±Z，并将四元数换算为横滚、俯仰及相对航向用于显示。板端优先用有效卡尔曼六轴融合，关闭滤波时使用原始六轴，`quat_kf` 指示输入来源。暂停订阅、断开或 `quat_ok=0` 会冻结预览并禁用归零；重新连接和退出演示清除网页参考。旧固件不提供四元数时提示更新，不在网页替代计算。

真实姿态在板端按实际采样时间融合，网页不再按遥测频率或 `seq` 差积分，因此低遥测频率不改变板端融合节拍。加速度幅值 0.7～1.3 g 时校正倾斜；采样异常间隔超过 250 ms 不积分丢失时段。世界 +Z 向上，相对航向从板端姿态初始化开始累计；六轴没有绝对北向参考，陀螺零偏和线性加速度仍影响姿态。方块表达传感器坐标，不自动识别 PCB 安装方向。

CSV 增加 `quat_ok`、`quat_kf`、`quat_w/x/y/z`，无效或缺失时四元数分量留空。姿态字段与原始／滤波六轴来自同一采样快照。演示模式生成模拟四元数，不代表实板测量。

「以当前姿态归零」只设置网页参考四元数，不发送板端命令，也不执行编码器清零。归零后所有角度显示相对该姿态的旋转。演示模式提供相互一致的重力和角速度模拟数据，供观察转动效果。

## 测试命令

无需安装依赖即可运行协议与串口生命周期测试（Node.js 22+）：

```powershell
node --test tools/web/tests/protocol.test.mjs
node --test tools/web/tests/motor-controls.test.mjs
node --test tools/web/tests/imu-attitude.test.mjs
node --test tools/web/tests/wifi.test.mjs
```

可选浏览器测试使用 Playwright，通过模拟 Web Serial 检查整个页面（运行前启动 `serve.py`）：

```powershell
node tools/web/tests/browser-smoke.cjs <Playwright模块路径> <Chrome或Edge程序路径>
node tools/web/tests/wifi-browser-smoke.cjs <Playwright模块路径> <Chrome或Edge程序路径>
```

真实板子联调：连接后应看到接收帧率及序号更新；转动/移动板子观察 IMU 与编码器值，暂停/恢复订阅，导出 CSV，最后停机并断开。页面不会自动向真实硬件注入演示数据。

Wi-Fi 浏览器测试使用本机真实 WebSocket 服务器和模拟 USB 配网，检查无线开关、关闭资源的异步确认、配置保留、开关拒绝与超时、密钥错误、双链路切换、四种模式、掉线恢复和 CSV 来源；不是实板射频或内存验证。实板操作见 [Wi-Fi 连接步骤](../docs/wifi.md#首次使用)。
